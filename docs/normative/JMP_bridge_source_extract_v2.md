**Estimated**, for both groups, but not because the YAML says so — because the code path that
consumes the YAML overrides it. `s10_estimation_lib_v1.py::build_target()` explicitly asserts
the loaded spec is the numeraire-fixed variant, then **un-fixes** `beta_c` and appends it as a

```

    raise AssertionError(...)
spec.utility_consumption_coef_fixed = None
L.append_coordinate(spec, "beta_c", BETA_C_BOUNDS, 1.0)   # bounds (0.05, 50.0), init 1.0
```

Result, quoted directly from the certified S11 report:
- SINGLES, line 77: `| beta_c | 2.03873182 | 0.2917295 | [0.05, 50] | no | no | NA |`
- COUPLES, line 172: `| beta_c | 2.10172027 | 0.2938791 | [0.05, 50] | no | no | NA |`

## 2. CRITERION FUNCTION

File: `MNL/dclaborsupply-monorepo/packages/dclaborsupply/src/dclaborsupply/likelihood/engine_jax.py`
(evaluator commit `55bb0d0ea7a1ad2d683f8b2b2a9f7bfb3d5118df`, confirmed live via `git rev-parse HEAD`
in `MNL/dclaborsupply-monorepo`). Function `build_jax_singles_ll` (lines 165–352); couples
analogue `build_jax_couples_ll` (from line 355) follows the identical assembly pattern with
per-spouse terms.

Module docstring invariant (lines 20–25):
```
Index construction is unchanged:
    V = u + log_h + log_w + log_market - log_prior
with worker-gated wage / market / occupation terms.
```

`index()` and `neg_ll()` closures (lines 292–352), quoted verbatim:
```python
    def index(theta):
        def P(name):
            # fixed_params take precedence (pinned, not in theta / pidx)
            if name in _fixed:
                return _fixed[name]
            return theta[pidx[name]]

        # ---- utility ----
        theta_l = P(theta_l_name) if theta_l_name else 0.0
        theta_c = P(theta_c_name) if theta_c_name else 0.0
        bc_l = jbox_cox(leisure, theta_l)
        bc_c = jbox_cox(consumption, theta_c)
        beta_l_coeff = P(beta_l0_name)
        for cname, arr in leis_shifters:
            beta_l_coeff = beta_l_coeff + P(cname) * arr
        beta_c = beta_c_fixed if beta_c_fixed is not None else P(spec.utility_consumption_coef + suffix)
        u = beta_l_coeff * bc_l + beta_c * bc_c  # beta_cl=0 for singles

        # ---- hours opportunity ----
        log_h = jnp.zeros_like(u)
        for cname, arr, uw in hours:
            x = arr * working if uw else arr
            log_h = log_h + P(cname) * x

        # ---- wage opportunity ----
        if _wage_fixed:
            log_w = jnp.zeros_like(u)
        else:
            mu = jnp.zeros_like(u)
            for cname, arr in wage_terms:
                mu = mu + (P(cname) if arr is None else P(cname) * arr)
            sigma = P(sigma_name)
            log_w_full = _jlog_wage_density(log_wage, mu, sigma, wage_support)
            log_w = jnp.where(working > 0, log_w_full, 0.0)

        # ---- market opportunity (+ centering) ----
        log_market = jnp.zeros_like(u)
        for cname, arr, uw in mkt:
            x = arr * working if uw else arr
            log_market = log_market + P(cname) * x
        if do_center:
            center_weights = (prior if center_prop else jnp.ones_like(prior))
            center_weights = center_weights * choice_domain.astype(jnp.float64)
            log_market = _center_proposal(log_market, center_weights, n_groups, n_alts)

        return jnp.where(choice_domain,
                         u + log_h + log_w + log_market - log_prior, -jnp.inf)

    def neg_ll(theta):
        # ---- composite V and grouped LL ----
        V = index(theta)
        V_obs, lse = jgroup_logsumexp(V, n_groups, n_alts, _ac, chosen_multiplicity)
        per = V_obs - lse                 # per-group positive log-likelihood
        if per_group:
            return per                    # vector (n_groups,) — jacrev => scores
        return -jnp.sum(per)              # negative LL (matches engine convention)

    return jax.jit(index if return_index else neg_ll), pidx
```

**(a) Choice-set normalization**: `jgroup_logsumexp` (lines 73–100) reshapes `V` to
`(n_groups, n_alts)`, subtracts the row max for numerical stability, and computes
`lse = mx[:,0] + log(sum(exp(V - mx)))` per group/household. `V_obs` is the chosen
alternative's index (weighted by `chosen_multiplicity` for repeated atoms under the
Criterion-A IID sampling convention, adding `log(n_y)` so duplicate draws are not
deduplicated). The per-household log-likelihood is the standard MNL softmax:
`per = V_obs - lse`; `neg_ll = -sum(per)`.

**(b) Where `log g − log q` enters**: the index is exactly
`V = u + log_h + log_w + log_market − log_prior`. `log_prior = log(prior)` is the log of the
**proposal/importance density q** (Item 3). `log_h`, `log_w`, `log_market` are the
**structural opportunity density g** components (hours-opportunity index, log-normal wage
density, market/occupation-access index). So `V = u + log(g) − log(q) = u + log(g/q)` — the
Aaberge–Colombino/RURO importance-sampling correction for a choice set sampled from `q` rather
than enumerated in full.

**Which objects are structural (g) vs purely numerical (q)**: `q` is the purely mechanical
importance-sampling proposal — `log_q_E` (employment), `log_q_H`/`_m`/`_f` (hours),
`log_q_W`/`_m`/`_f` (wage), `log_q_Occ`/`_m`/`_f` (occupation) — all built in
`alternatives/continuous.py::generate_draws_long` as **Uniform** densities
(`log_q_hours = -log(h_max - h_min)`, `log_q_wage = -log(w_max - w_min)`) or empirical
occupation frequencies. `g`, the structural opportunity density, is instead carried by the
spec's `hours_opportunity`, `wage_opportunity` (log-normal), `market_opportunity`, and
`occupation_opportunity` blocks — their coefficients (`beta_E`, `beta_h_pt1/pt2/f35/ft/lh`,
`beta_E_gsur`, region/urban dummies, `beta_occ_*`, `beta_w0`, `beta_w_educL/H`,
`beta_w_pexp/pexp2`, `sigma`) are the estimated parameters entering `u/log_h/log_w/log_market`
in engine_jax.py (Item 2).

**Does the log-normal wage density serve both roles?** No. Under `wage_opportunity.specification:
log_normal` (the setting actually used), the **structural** `log_w` is the estimated log-normal
density (mean linear in education/experience, variance `sigma²`) — that is `g`'s wage
component. The **proposal** `log_q_W`/`log_q_wage` is a separate, distinct **Uniform[w_min,
w_max]** density (`w_min=2.0, w_max=170.0` at draw-generation time in `continuous.py`, restated
as `wage_support_lower/upper = 2.0, 590.0` in the estimation spec builders). The two are
different objects that happen both to concern wages; the log-normal serves only `g`, not `q`.

## 4. NEAR-FLOOR MASS ON [5, 7.5] HOURS — ANALYTICAL ONLY, NO HOUSEHOLD DATA

This section reports what the model's functional form implies analytically. It is **not** a
computed household share and does not draw on any microdata (consistent with the read-only,
no-data-upload scope of this pass).

Hours support constants (`MNL/dclaborsupply-monorepo/.../alternatives/continuous.py`):
```python
DEFAULT_H_MIN = 5.0
DEFAULT_H_MAX = 70.0
```
Conditional-on-working hours draws are Uniform on `[5.0, 70.0]` — i.e. the proposal `q`'s
support strictly *includes* `[5, 7.5]` at its left edge, not below it.

The structural `hours_opportunity` block is a **piecewise-constant indicator index**, not a
continuous function of `h` — no Box-Cox or other smooth transform is applied to hours itself
(Box-Cox applies only to `leisure` and `consumption`):
```yaml
hours_opportunity:
  shifters:
  - variable: working / working_pt1 / working_pt2 / working_f35 / working_ft / working_lh
    coefficient: beta_E / beta_h_pt1 / beta_h_pt2 / beta_h_f35 / beta_h_ft / beta_h_lh
```
with indicator bands `pt1=[17.5,21.5]`, `pt2=[28.5,30.5]`, `f35=[33.5,36.5]`, `ft=[36.5,40.5]`,
`lh=[44.5,70]` — all strictly above 17.5 hours. On `[5, 7.5]` none of these bands are active
(all indicators = 0), so `log_h(h) = beta_E · 1{working}`, a constant on that interval, for
singles male, singles female, couples male (`beta_E_m`), and couples female (`beta_E_f`) alike
— the band boundaries are identical across groups; only the coefficient value differs.

**Analytical conclusion**: because (i) the proposal's hours support is Uniform on `[5,70]`
by construction, and (ii) the structural hours-opportunity index on `[5,7.5]` reduces to
`exp(beta_E)`, a strictly positive quantity for any finite estimated `beta_E`, the combined
opportunity density has **positive mass on [5, 7.5] hours for all four groups (singles
male/female, couples male/female) by construction of the functional form**, independent of
the fitted parameter values. There is no boundary restriction inside `[5,7.5]` — the only
floor sits exactly at 5.0, the left edge, not below it, so nothing in the model's structure
zeroes out this sub-interval.
